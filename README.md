# WebGPU Path Tracer Next

Спектральный браузерный рендерер по [плану реализации](docs/implementation-plan.md).

## Запуск

Требуется Node.js 22.12+ (локально проверяется Node.js 24) и Chrome/Edge с аппаратным ускорением и доступным WebGPU.

```sh
npm ci
npm run dev
```

Открыть адрес Vite в браузере. Для публикации: `npm run build`, затем разместить `dist/` на статическом HTTPS-хостинге. `npm run preview` проверяет собранное приложение локально.

## Проверки

```sh
npm test
npm run build
npm run test:browser
```

Браузерные тесты используют установленный Google Chrome через Playwright, без флагов включения нестандартного WebGPU. Dev-сервер тестов автоматически запускается и останавливается. Снимок canvas сохраняется в `test-results/foundation.png`.

## Текущий результат

Реализовано основание этапа 1: strict TypeScript/Vite, WebGPU initialization, compute shader → линейная `rgba16float` текстура → display pass с tone mapping и sRGB, ограниченное разрешение, resize, pause/resume, остановка в фоновой вкладке, диагностика и освобождение ресурсов. Неожиданная потеря device запускает повторную инициализацию диагностического кадра.

Внутреннее разрешение сохраняет соотношение сторон и ограничено 307 200 пикселями и реальным `maxTextureDimension2D`. Показанная память учитывает управляемую текстуру и uniform buffer; она не включает память драйвера и canvas swapchain. Время завершения включает CPU и ожидание очереди, а не только GPU. Одновременно выполняется не более одной отправки команд.

Изображение сейчас является диагностикой compute-to-canvas. BVH, PT, SPPM и конечная сцена ещё не реализованы. `FoundationRenderer` — временный стенд первого этапа; публичный scene/Renderer-контракт из плана будет вводиться вместе со сценой.

Принудительная потеря device, ограниченные device limits и статический HTTPS-хостинг пока не проверены. Фактические результаты локального запуска записаны в [статусе реализации](docs/implementation-status.md).
