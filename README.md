# WebGPU Path Tracer Next

Спектральный браузерный рендерер по [плану реализации](docs/implementation-plan.md).

## Запуск

Требуется Node.js 22.12+ (локально проверяется Node.js 24) и Chrome/Edge с аппаратным ускорением и доступным WebGPU.

```sh
npm ci
npm run dev
```

Открыть адрес Vite в браузере. Для публикации: `npm run build`, затем разместить `dist/` на статическом HTTPS-хостинге. `npm run preview` проверяет собранное приложение локально.

## Проверки

```sh
npm test
npm run build
npm run test:browser
```

Браузерные тесты используют установленный Google Chrome через Playwright, без специальных WebGPU-флагов. Dev-сервер тестов автоматически запускается и останавливается. Снимки canvas сохраняются в `test-results/`. Фиксированный RGB-кадр на 128 spp хранится в `docs/validation/` (PNG, линейный PFM, JSON с настройками).

## Текущий результат

Реализованы этапы 1–8: основание WebGPU, пересечения, RGB path tracer, сплошное стекло, спектральный PT, RGB и спектральный SPPM, конечная сцена Suzanne. Рендерер накапливает непрямой свет, перенос цвета и мягкие тени; path tracer использует NEE, power-heuristic MIS и Russian roulette после пятого взаимодействия. Глубина по умолчанию — 32 для Suzanne и 8 для диффузной контрольной сферы, программно доступна 1–64. Конечная глубина ограничивает оценку переноса; абсолютная несмещённость не заявляется. Физическое ядро сверяется с [PBRT: A Better Path Tracer](https://pbr-book.org/4ed/Light_Transport_I_Surface_Reflection/A_Better_Path_Tracer).

Сцена содержит открытую спереди коробку Корнелла 2×2×2 м, потолочный прямоугольник и единую замкнутую Suzanne из N-BK7. Ширина модели — 1,2 м, центр bounding box — `(0,1,0)`, камера направлена в центр с вертикальным FOV 40°. Контрольная сфера доступна через «Сцена» или `/?scene=control`. Worker проверяет меши, запекает affine transforms в мировые координаты и строит бинарный SAH BVH с 16 корзинами. Размер узла — 32 байта, обычного листа — до 4 треугольников, глубина ограничена 48 уровнями при стеке GPU из 64 элементов. Упаковка основана на WGSL reflection из `webgpu-utils`.

GPU обходит ближайший дочерний узел первым и предоставляет `closestHit`/`anyHit`. Пересечение треугольников использует sheared ray-space edge functions по [PBRT](https://pbr-book.org/4ed/Shapes/Triangle_Meshes). Ошибки индексов, стека и нечисловых значений диагностируются явно. Проверена устойчивость на фиксированном наборе лучей и текущем масштабе сцены; произвольные экстремальные координаты не проверялись.

Перетаскивание canvas вращает камеру, колесо меняет расстояние, кнопка сбрасывает камеру. Доступны RGB PT и debug views нормалей, глубины, числа посещённых BVH-узлов. Light-only и BSDF-only предназначены для сравнения с MIS. Экспозиция сохраняет накопление; камера, сцена, разрешение и настройки интегратора сбрасывают его. При паузе изменение камеры выполняет один полный новый проход, затем накопление останавливается.

Raw accumulation хранится в f32 отдельно от отображаемой `rgba16float` текстуры. Path tracing запускается пакетами 64×64 пикселя; spp растёт после полного прохода всех tiles. Точное число samples каждого пикселя доступно в линейном `capture()`. PT использует 7 storage-buffer bindings, каждый SPPM pass — не более 8; optional GPU features не требуются.

Внутреннее разрешение сохраняет соотношение сторон. По умолчанию UI использует бюджет 320×240, доступны 160×120 и 640×480; дополнительно учитываются реальные texture и storage-buffer limits. Показанная память учитывает постоянные управляемые ресурсы, но не временный capture readback, память драйвера и canvas swapchain. Время завершения включает CPU и ожидание очереди, а не только GPU. Одновременно выполняется не более одной отправки render-команд.

Sampler использует 512 Sobol dimensions и nested binary Owen scrambling на всех 24 битах f32-сэмпла. Размеры камеры и каждого взаимодействия закреплены. Готовый ресурс входит в проект; повторная подготовка: `npm run assets:sobol` (нужен интернет). Источник закреплён commit SHA, метаданные и лицензии хранятся рядом с ресурсом.

Контрольный кадр воспроизводится командой `npm run capture:control`: скрипт сам запускает и завершает Vite на порту 5175 и Chrome. Этот кадр предназначен для регрессии GPU-движка. Независимая проверка прямого света использует детерминированную численную квадратуру и сравнивает MIS/light/BSDF на 65 536 путях.

По умолчанию открывается стеклянная Suzanne в RGB PT; контрольная сфера изначально диффузная. Материал доступен через «Материал», RGB/спектральный режим — через «Перенос», PT/SPPM — через «Интегратор». Denoiser ещё не реализован. `IntersectionRenderer` предоставляет `setSettings`, `setExposure` и линейный `capture()`; загрузка PNG/PFM из интерфейса появится вместе с полным экспортом. CPU-сцена сохраняется для восстановления ресурсов после потери device.

Принудительная потеря device, ограниченные device limits и статический HTTPS-хостинг пока не проверены. Фактические результаты локального запуска записаны в [статусе реализации](docs/implementation-status.md).
## Стекло: этап 4

Пресет «Стекло RGB» задаёт сплошную контрольную сферу с IOR 1.5 и RGB-поглощением `[0.15, 0.03, 0.01]` в обратных метрах. При смене материала накопление сбрасывается, глубина становится 32. «Диффузный» сохраняет контрольную сцену предыдущего этапа.

Диэлектрик использует точный Fresnel, Snell, TIR, Beer–Lambert и delta-события без неприменимого continuous MIS. Radiance transmission учитывает η²; отдельный importance-режим BSDF проверен для будущего photon tracer. Вложенные и пересекающиеся стеклянные объёмы не поддерживаются. Открытые или неверно ориентированные сетки отклоняются; обнаруженная несогласованная граница или выход из незавершённого объёма диагностируется ошибкой 4.

Стеклянный BSDF использует сглаженные shading-нормали, границы среды — геометрические. События с неверной геометрической стороной получают нулевой вес. Adjoint-поправка для importance-переноса проверена отдельно; diffuse BSDF пока сохраняет геометрическую нормаль.

`npm run capture:control -- --glass` сохраняет отдельные [PNG](docs/validation/stage4-cornell.png), PFM и JSON для этапа 4, не перезаписывая этап 3. Это GPU regression capture, а не независимый эталон.

## Спектральный PT: этап 5

Выберите «Перенос → Спектральный» и «Материал → N-BK7». Пресет «N-BK7 без дисперсии» сохраняет то же спектральное поглощение и фиксирует IOR на d-линии 587.6 нм. В RGB-режиме оба N-BK7 пресета используют этот фиксированный IOR.

Одна длина волны равномерно выбирается на путь в диапазоне 360–830 нм: `p(λ)=1/470 nm⁻¹`, Sobol dimension 2. Свет, BSDF, IOR и поглощение оцениваются на этой же λ. Накопление — CIE XYZ с весом `L(λ)·CIE(λ)/(p(λ)·106.856895)`. Перевод в линейный sRGB выполняется после усреднения; gamut clipping, экспозиция и tone mapping относятся только к отображению. `capture()` возвращает `linearXyz`, `linearRgb` и `accumulationSpace`; отрицательные компоненты raw RGB сохраняются.

CIE 1931 2° и D65 взяты из закреплённой версии PBRT, источник нормирован на Y=1. Стены используют явно заданные табличные демонстрационные спектры, а не измеренные спектры Cornell. Нейтральным RGB-материалам соответствует плоский спектр; для остальных спектральный режим требует явных таблиц. Автоматического RGB-to-spectrum восстановления нет.

Sellmeier N-BK7 и внутреннее пропускание взяты из [SCHOTT, страница 13](https://www.schott.com/en-gb/products/optical-glass/-/media/Project/OnEx/Products/O/optical-glass/Downloads/schott-optical-glass-collection-datasheets-english-may2019.pdf?rev=5358bb64e13a44f2b37f5065490509af). Для IOR nm переводятся в µm; `σa=-ln(τi)/0.01 m`, затем коэффициент поглощения линейно интерполируется. Коэффициенты и источники включены в `public/assets/spectra.json`; лицензия и copyright notices находятся рядом. Повторная подготовка: `npm run assets:spectra`.

`npm run capture:control -- --spectral` сохраняет [контрольный PNG](docs/validation/stage5-cornell.png), RGB PFM, отдельный XYZ PFM, настройки и [численную приёмку](docs/validation/stage5-spectral-checks.json). Закрытая 60° призма в GPU-тесте разделяет 400–800 нм на 2.25°; при постоянном IOR разделение исчезает. На 128 spp обычный спектральный PT ещё заметно шумит, особенно в каустике. Спектральный photon gather и denoiser относятся к следующим этапам.

## RGB SPPM: этап 6

Выберите «Материал → Стекло RGB», «Перенос → RGB» и «Интегратор → SPPM». Глубина становится 32. По умолчанию испускается 16 384 фотонных пути на итерацию пакетами по 1 024; начальный радиус — 0.03 м. Параметры доступны через `setSettings()`.

Camera pass проходит delta-события до первой диффузной поверхности и отдельно оценивает прямой свет через NEE. Photon pass пропускает первое прямое диффузное попадание, сохраняет последующие, в том числе после стекла, и продолжает путь после diffuse scattering. Каждый путь резервирует `maxDepth+1` слотов: заполнение пакета не отбрасывает энергию. Пространственный hash использует только целочисленные atomic heads; один поток на visible point суммирует поток в f32, проверяя координаты ячейки, расстояние, поверхность и нормаль.

Progressive update с α=2/3 выполняется один раз после всех пакетов, по [PBRT SPPM](https://pbr-book.org/3ed-2018/Light_Transport_III_Bidirectional_Methods/Stochastic_Progressive_Photon_Mapping). Нормировка учитывает все испущенные пути, включая промахи. При нуле попаданий радиус, N и τ сохраняются. Camera/gather portions ограничены 128×128 пикселями. Отображение и `capture()` используют последнюю завершённую итерацию; частичная итерация её не меняет. Счётчик `samples` означает итерации SPPM, `emittedPhotons` — испущенные пути. Смена камеры или настроек сбрасывает всю историю; экспозиция её сохраняет.

Visible point и история занимают 112 байт на пиксель, photon — 64 байта. Буферы проверяются по реальным device limits и освобождаются при возврате в PT. GPU-тесты проверяют hash-коллизии против brute force, progressive update, нулевые попадания, ошибочные ссылки, прямой свет против квадратуры, неизменность результата при разбиении пакетов и отмену итерации.

`npm run capture:control -- --sppm` сохраняет [PNG](docs/validation/stage6-cornell.png), линейный PFM, настройки, [сходимость 8/16/32/64 итераций](docs/validation/stage6-convergence.json) и [проверку hash](docs/validation/stage6-hash-checks.json). Кадр 128×96 на 64 итерациях использует 1 048 576 путей; под сферой видна каустика. Конечный радиус создаёт kernel bias; полная энергетическая приёмка и оценка влияния радиуса относятся к этапу 10.

## Спектральный SPPM: этап 7

Выберите «Перенос → Спектральный», «Интегратор → SPPM» и «Материал → N-BK7». Эти переключатели теперь независимы. Пресет без дисперсии оставляет спектральное поглощение и фиксирует IOR на d-линии.

Одна λ используется всеми camera/photon subpaths итерации. Owen–Sobol dimension 2 с общим stream ID стратифицирует длины волн между итерациями; выровненные блоки из 2ⁿ итераций покрывают 2ⁿ strata. Emission, reflectance, IOR и Beer–Lambert используют ту же λ. Камерный throughput и photon flux не делятся на PDF независимо: `CIE(λ)/(p(λ)·106.856895)` применяется ровно один раз к direct и весу visible point. Photon flux остаётся спектральным скаляром в существующем vec3 layout; gather и progressive statistics накапливают XYZ. Размер буферов и предел 8 storage bindings не изменились.

`capture()` сохраняет raw XYZ и отрицательные компоненты линейного RGB. Экспозиция не меняет их; RGB/spectral, PT/SPPM и смена камеры очищают историю, включая частичную итерацию. Общая λ даёт заметный цветовой шум на первых итерациях; на 128 итерациях контрольный кадр ещё не считается финальным изображением.

`npm run capture:control -- --sppm --spectral` сохраняет [PNG](docs/validation/stage7-cornell.png), RGB/XYZ PFM и [сходимость](docs/validation/stage7-convergence.json). Контроль: 128×96, 128 итераций, 2 097 152 пути, N-BK7, radius0.03, depth32. Это GPU regression capture.

Независимые численные проверки используют интеграл D65, квадратуру двух Lambertian propagation kernels и угловую квадратуру стеклянной пластины с внутренними отражениями. Реальный photon pass призмы проверяется против независимых CPU Snell/Fresnel, пересечений и Beer–Lambert; при постоянном IOR разделение попаданий исчезает. Для внешней приёмки есть `npm run validate:spectral-sppm -- --pbrt <путь к pbrt.exe>`; отдельный случай: `--case prism`, `--case slab`, `--case cornell` или `--case constant`. Нужен PBRT v4 commit `b4ce9687e6c695f5582997c61b0c66cf064bdb4a`, CPU build. Исходники: [mmp/pbrt-v4](https://github.com/mmp/pbrt-v4); сборка через CMake/MSVC, targets `pbrt_exe` и `imgtool`.

Экспорт использует одинаковые world triangles, shading normals, табличные спектры и medium absorption. PBRT автоматически нормирует площадной свет: `scale` восстанавливает исходную спектральную radiance, а ISO `100/106.856895` согласует выход CIE1931 с нормированным XYZ движка. White balance выключен, box filter соответствует pixel jitter. Два независимых PBRT seed проверяют устойчивость средней энергии; результаты и `.pbrt` сцены сохраняются в `docs/validation/stage7-*-comparison.json` и соответствующих PFM. Критерии: разброс reference ROI ≤2%, ошибка SPPM ROI ≤5%. Эти контрольные случаи не заменяют полную приёмку конечной сцены, радиусов, глубин и браузерной матрицы.

## Suzanne: этап 8

Готовый меш содержит 49 370 вершин и 98 736 треугольников, включая сглаженные нормали. Бинарный ресурс 2,37 MB входит в сборку; загрузчик проверяет SHA-256 и layout. Blender и интернет для запуска приложения не нужны. Смена сцены сохраняет положение камеры и освобождает предыдущие GPU-ресурсы.

[Скрипт подготовки](scripts/prepare-suzanne.py) создаёт исходный Suzanne primitive в Blender 4.4.3, закрывает отверстия, сглаживает, объединяет глаза и голову voxel remesh, затем выполняет окончательные subdivision и triangulation. Ориентация, замкнутость, связность и самопересечения проверяются до окончательного subdivision и на готовых f32-треугольниках. Детектор имеет положительные контрольные примеры, включая пересечение с общей вершиной. Повторная подготовка даёт тот же SHA-256 готового меша.

Редактируемый исходник находится в [assets/source/suzanne.blend](assets/source/suzanne.blend), происхождение и результаты проверок — в [метаданных](src/assets/suzanne-meta.json), сведения об источнике — в [SUZANNE-NOTICES.txt](public/assets/SUZANNE-NOTICES.txt). Команда подготовки: `blender --background --factory-startup --python-exit-code 1 --python scripts/prepare-suzanne.py`.

`npm run capture:control -- --suzanne` сохраняет raw-сцену без denoiser: [PNG](docs/validation/stage8-cornell.png), линейные RGB/XYZ PFM, настройки и сходимость. Параметры: 256×192, 256 спектральных SPPM-итераций, seed17, depth32, radius0.03. Сцена соответствует размерам и размещению из плана; проверка против PBRT всей Suzanne и полная приёмка изображения относятся к этапу 10. Следующий этап — 9: режимы Preview / Reference / Quality, denoiser и экспорт.
