# WebGPU Path Tracer Next

Спектральный браузерный рендерер по [плану реализации](docs/implementation-plan.md).

## Запуск

Требуется Node.js 22.12+ (локально проверяется Node.js 24) и Chrome/Edge с аппаратным ускорением и доступным WebGPU.

```sh
npm ci
npm run dev
```

Открыть адрес Vite в браузере. Для публикации: `npm run build`, затем разместить `dist/` на статическом HTTPS-хостинге. `npm run preview` проверяет собранное приложение локально.

## Проверки

```sh
npm test
npm run build
npm run test:browser
```

Браузерные тесты используют установленный Google Chrome через Playwright, без специальных WebGPU-флагов. Dev-сервер тестов автоматически запускается и останавливается. Снимки canvas сохраняются в `test-results/intersections.png`, `normal.png` и `depth.png`.

## Текущий результат

Реализованы основание этапа 1 и пересечения этапа 2: strict TypeScript/Vite, WebGPU initialization, compute → линейная `rgba16float` текстура → display pass с tone mapping и sRGB, ограниченное разрешение, resize, pause/resume, остановка в фоновой вкладке, диагностика и освобождение ресурсов. CPU-сцена сохраняется для повторной загрузки после неожиданной потери device.

Сцена содержит коробку Корнелла 2×2×2 м, потолочный прямоугольник и замкнутую контрольную сферу. Worker проверяет меши, запекает affine transforms в мировые координаты и строит бинарный SAH BVH с 16 корзинами. Размер узла — 32 байта, обычного листа — до 4 треугольников, глубина ограничена 48 уровнями при стеке GPU из 64 элементов. Упаковка основана на WGSL reflection из `webgpu-utils`.

GPU обходит ближайший дочерний узел первым и предоставляет `closestHit`/`anyHit`. Пересечение треугольников использует sheared ray-space edge functions по [PBRT](https://pbr-book.org/4ed/Shapes/Triangle_Meshes). Ошибки индексов, стека и нечисловых значений диагностируются явно. Проверена устойчивость на фиксированном наборе лучей и текущем масштабе сцены; произвольные экстремальные координаты не проверялись.

Перетаскивание canvas вращает камеру, колесо меняет расстояние, кнопка сбрасывает камеру. Доступны debug views нормалей, глубины и числа посещённых BVH-узлов. Изменение камеры или вида перерисовывает кадр и при включённой паузе.

Внутреннее разрешение сохраняет соотношение сторон и ограничено 307 200 пикселями и реальным `maxTextureDimension2D`. Показанная память учитывает управляемую текстуру, геометрию, BVH, uniform и диагностические buffers; она не включает память драйвера и canvas swapchain. Время завершения включает CPU и ожидание очереди, а не только GPU. Одновременно выполняется не более одной отправки команд.

Изображение сейчас является диагностикой пересечений без освещения. PT, SPPM и конечная сцена со стеклянной Сюзанной ещё не реализованы. `IntersectionRenderer` принимает `SceneDescription`, `setCamera` и `setDebugView`; полный Renderer-контракт из плана будет завершён вместе с интеграторами и экспортом.

Принудительная потеря device, ограниченные device limits и статический HTTPS-хостинг пока не проверены. Фактические результаты локального запуска записаны в [статусе реализации](docs/implementation-status.md).
