# WebGPU Path Tracer Next

Браузерный рендерер на TypeScript и WGSL: RGB и спектральный path tracing (PT), progressive photon mapping (SPPM), software BVH и редактор демонстрационной сцены. [Аудит и дорожная карта](docs/development-roadmap.md) описывают состояние и следующие задачи.

## Запуск

Требуются Node.js 22.12+ и Chrome/Edge с доступным WebGPU и аппаратным ускорением.

```sh
npm ci
npm run dev
```

Откройте адрес Vite. `npm run build` проверяет TypeScript и создаёт `dist/`; `npm run preview` запускает локальный просмотр сборки. Для публикации нужен статический HTTPS-хостинг.

## Возможности и настройки

По умолчанию загружается **Suzanne high poly**, диэлектрик, профиль **Quality: spectral SPPM**, глубина 32, 16 384 фотонных пути за итерацию, batch 1024, начальный радиус 0,03 м. Пиксельный бюджет — 640×480, память — 192 MiB. `/?scene=control` открывает контрольную сферу с другими настройками: RGB PT; это отдельная контрольная сцена.

Доступны Cornell/Open, площадной источник света, постоянное окружение и HDR, встроенные Suzanne high poly, Suzanne, Rastagotchi, Happy Buddha и сфера. Можно загрузить локальный OBJ, ремонтировать отверстия и ориентацию оболочек, менять преобразования, материал и освещение. OBJ переносит геометрию и нормали; MTL и UV-текстуры не поддерживаются. Ремонт не является полной проверкой самопересечений.

Редактор предлагает `diffuse`, `dielectric`, `textured`; отдельный выбор текстуры — мрамор или лава. Диэлектрик поддерживает гладкую и шероховатую поверхность, IOR, художественную дисперсию Cauchy/число Аббе, поглощение и режим Auto/Volume/Thin. Измеренный N-BK7 остаётся в контрольных сценах ядра. Тонкое стекло не даёт объёмного преломления, поглощения и линзовых каустик. Спектральное восстановление RGB и HDR — приближение, а не измеренный спектр.

Фильтр à-trous, экспозиция и tone mapping не меняют raw-накопление. Первые стеклянные поверхности по умолчанию сохраняются без сглаживания. PNG сохраняет отображаемый результат, PFM — линейный RGB, JSON — параметры и сведения о накоплении. Ссылка настроек восстанавливает сцену, параметры и камеру; **локальные OBJ/HDR через ссылку не передаются**.

Разрешение задаёт пиксельный бюджет, а не гарантированный размер: учитываются viewport, DPR, память и лимиты устройства. Максимумы настроек — 4K и 4096 MiB; фактическая вместимость может быть меньше. Поддерживаются несколько оболочек, до 32 одновременно активных; самопересечения одной оболочки и точно совпадающие поверхности не поддерживаются. Редактор пока привязан к демонстрационной сцене; GLB, измеренные проводники, UV-текстуры и объёмное рассеяние — задачи дорожной карты.

## Проверки и известные проблемы

Для диэлектриков доступны «Царапины», «Потёртости», «Отпечатки пальцев» и отдельный «Вариант рисунка». Rastagotchi получает средний износ (0,5 для каждого эффекта), остальные модели — чистую поверхность. Следы процедурные, закреплены в локальных координатах модели и влияют на шероховатость и нормаль в PT/SPPM. Нулевые значения выключают эффекты; ссылки настроек и JSON экспорта сохраняют параметры. Геометрические сколы и изменение силуэта не моделируются. PBRT reference export требует выключить износ, поскольку не переносит эти процедурные следы.

```sh
npm test
npm run build
npm run test:browser
```

На commit `70f319e7d5d64d5d10c33cd088e6e470acb57919` при подготовке документации 05.10.2026 повторно прошли **101 unit-тест в 21 файле**, TypeScript и production build. Инвентаризация Playwright: **52 теста в 20 файлах**. Полный браузерный набор в этом пакете не запускался.

Playwright использует установленный Google Chrome, один worker и автоматически управляет dev-сервером. GPU-результаты требуют указания адаптера; программный адаптер следует обозначать отдельно. Предыдущий выборочный аудит: 4 браузерных теста упали, 1 прошёл; GPU-сэмплер совпал с CPU на 2496 значениях. Эти результаты сейчас не повторялись; подробные границы — в [дорожной карте](docs/development-roadmap.md).

Из предыдущего аудита известны: `intersection` на первом проходе камеры стандартной high-poly Suzanne при 817×375; ранняя ошибка запуска без WebGPU; устаревшие UI-фикстуры, короткие ожидания и перехват служебного OBJ-импорта Vite. Это отдельные задачи исправления, а не доказательство неисправности всех режимов.

Диагностические команды: `npm run benchmark`, `npm run validate:runtime`, `npm run validate:spectral-sppm`, `npm run validate:quality -- --pbrt <путь-к-PBRT-v4>`. Capture-команды пока требуют проверки выходного каталога: некоторые сохраняют исторические имена `stage*`; не перезаписывайте архив проверки.
