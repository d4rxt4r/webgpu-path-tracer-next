# WebGPU Path Tracer Next

Спектральный браузерный рендерер по [плану реализации](docs/implementation-plan.md).

## Запуск

Требуется Node.js 22.12+ (локально проверяется Node.js 24) и Chrome/Edge с аппаратным ускорением и доступным WebGPU.

```sh
npm ci
npm run dev
```

Открыть адрес Vite в браузере. Для публикации: `npm run build`, затем разместить `dist/` на статическом HTTPS-хостинге. `npm run preview` проверяет собранное приложение локально.

## Проверки

```sh
npm test
npm run build
npm run test:browser
```

Замеры скорости, сравнение raw-качества и проверенные варианты оптимизации: [docs/performance.md](docs/performance.md). Повторный контрольный замер: `npm run benchmark -- --tag current-control --cases suzanne --modes spectral-pt,spectral-sppm --width 640 --height 480 --pt 4 --sppm 1`.

Браузерные тесты используют установленный Google Chrome через Playwright, без специальных WebGPU-флагов. Dev-сервер тестов автоматически запускается и останавливается. Снимки canvas сохраняются в `test-results/`. Фиксированный RGB-кадр на 128 spp хранится в `docs/validation/` (PNG, линейный PFM, JSON с настройками).

## Текущий результат

В «Сцена и свет» кнопка **Загрузить OBJ** заменяет центральный объект собственной моделью. Файл читается локально в Worker; готовые Suzanne, Happy Buddha и сфера остаются в списке, как и последний загруженный OBJ до перезагрузки страницы. Импортируются геометрия и нормали, включая smoothing groups и простые многоугольники, включая неплоские грани (триангуляция проекции сохраняет исходные 3D-вершины); MTL и UV-текстуры не загружаются. Модель с вертикальной осью Y центрируется и пропорционально вписывается до максимального размера 1,2 м. Пределы: 128 MiB и 2 млн треугольников после триангуляции; фактическая вместимость зависит от памяти и лимитов GPU. Все объекты можно вращать по X, Y и Z, в порядке X → Y → Z.

Замена объекта сохраняет материал, камеру, свет и настройки рендера, сбрасывая трансформацию нового объекта. Исключение — готовая сцена **Rastagotchi**: при её выборе устанавливается стекло с лёгким зелёным оттенком, IOR 1,5 и шероховатостью 0,03. Suzanne high poly остаётся стартовой сценой. OBJ с замкнутыми корректно ориентированными оболочками использует объёмное стекло; открытые и несовместимые модели автоматически используют **тонкое стекло** с отражением и прямым пропусканием по модели PBRT ThinDielectricBxDF. Оно не имеет объёмного преломления, поглощения и линзовых каустик. Проверка замкнутости не является полной проверкой самопересечений. При ошибке импорта или нехватке ресурсов предыдущий объект сохраняется. Raw JSON включает имя OBJ, число треугольников и вращения; сам файл OBJ в экспорт не включается.

Импортёр пробует несколько проекций неплоской грани. Пересекающиеся в 3D рёбра одной грани разделяются в точке пересечения с интерполяцией нормалей; соседние грани получают те же точки, чтобы избежать разрывов. Это не выполняет булево объединение пересекающихся оболочек модели.

Галочка **Замкнуть модель** согласует ориентацию граней и закрывает простые отверстия загруженного OBJ в Worker. Сначала удаляются повторяющиеся грани и противоположные совпадающие внутренние пары, создающие неоднозначные рёбра. Оставшиеся сжатые неоднозначные рёбра стягиваются в точку только при длине и смещении вершин не более 0,1% максимального размера модели. Исходные массивы сохраняются: снятие галочки возвращает исходную геометрию. Каждая связанная оболочка ремонтируется отдельно; результат принимается только если все оболочки стали замкнутыми объёмами. При крупных неоднозначных рёбрах, ветвлениях или неподходящих контурах остаётся весь исходный OBJ с номером проблемной оболочки и объяснением причины. Предел одного контура — 4096 вершин, общий предел — 2 млн треугольников и доступная память GPU. Самопересечения не исправляются. Результат ремонта кешируется до загрузки другого OBJ и включается в Raw JSON вместе с числом оболочек и отчётом по компонентам.

Раздельные, вложенные и пересекающиеся оболочки одного OBJ используют общий материал, сохраняя независимые границы объёмов. В пересечении одинаковых стёкол нет дополнительного преломления и удвоения поглощения. PT и SPPM учитывают до 32 одновременно активных оболочек; общее число оболочек этим значением не ограничено. Камера может находиться внутри нескольких оболочек. Самопересечения одной оболочки и точно совпадающие поверхности не поддерживаются; неоднозначные переходы диагностируются.

Режимы Reference и Quality доступны также в вариантах Full HD, QHD и 4K. Ручной бюджет памяти расширен до 4096 MiB, число фотонных путей за итерацию — до 4194304, пакет — до 16384. Стартовые настройки для встроенной графики сохранены. Разрешение задаёт пиксельный бюджет: фактический размер зависит от области просмотра, DPR, памяти и лимитов GPU; бюджет памяти не является измерением доступной VRAM.

Иконка `i` рядом с настройкой показывает пояснение при наведении, фокусе или нажатии; Escape закрывает подсказку. Нажатие колёсика на числовом поле или ползунке возвращает только эту настройку к стандартному значению, независимо от выбранного пресета. Для параметров материала и положения объекта учитываются текущий материал и сцена. Отключённые поля не сбрасываются.

В «Сцена и свет → Объект» добавлен **Happy Buddha**, в «Материал → Тип» — **Камень / мрамор** и **Лава**. Они доступны и для Suzanne/сферы. Мрамор — тёмный полированный камень с белыми объёмными прожилками; лава — тёмная корка со светящимися оранжевыми участками. Лава участвует в освещении сцены, включая площадное семплирование и фотонный проход SPPM. Рисунок закреплён в координатах объекта и не скользит при перемещении, повороте и масштабе.

Группа «Текстура и поверхность» позволяет менять частоту, искажение, ширину рисунка и полировку; для лавы также доступны интенсивность и цвет свечения по температуре. Настройки применяются автоматически в RGB/спектральном PT и SPPM. Прямые ссылки: `/?scene=buddha` и `/?scene=buddha&material=lava`. Контрольные снимки: [мрамор](docs/validation/buddha-marble-filtered.png) и [лава](docs/validation/buddha-lava-filtered.png); рядом сохранены raw PNG, PFM и параметры. Воспроизведение: `node scripts/capture-final.mjs --buddha` и `node scripts/capture-final.mjs --buddha --lava`.

Модель — полный [Happy Buddha, Stanford Computer Graphics Laboratory](https://graphics.stanford.edu/data/3Dscanrep/): 543 652 вершины и 1 087 716 исходных треугольников в [Buddha.obj](assets/Buddha.obj), около 42,6 MB. Конвертация PLY → OBJ сохраняет координаты, грани и компоненты без упрощения, remesh или удаления деталей. Повторный экспорт: `python scripts/export-buddha-original.py`; сведения об источнике и хешах — в [Buddha-source.json](assets/Buddha-source.json), условия использования — в [BUDDHA-NOTICES](public/assets/BUDDHA-NOTICES.txt). Грани нулевой площади пропускаются только при загрузке и учитываются в статусе модели; исходный OBJ содержит их без изменений. Высота около 1,7 м задаётся нормализацией при загрузке. Полный скан требует больше времени и памяти; автоматического упрощения нет.

Стартовый вид теперь ориентирован на [референс Adrian Russell](https://adrianrussell.co.uk/images/blog/raytracer-1/suzanne.png): квадратный кадр, синее стекло, зелёная стена слева и красная справа. «Синее стекло» — художественный пресет с IOR 1.7 и селективным объёмным поглощением, а не даташит N-BK7. Материал N-BK7 остаётся в настройках; исходные численные сцены и артефакты приёмки сохранены. Контрольный рендер нового вида: `npm run capture:reference`, [PNG](docs/validation/reference-look-filtered.png), [raw PNG](docs/validation/reference-look-raw.png), PFM и JSON рядом.

ЛКМ вращает камеру, зажатое колесо перемещает камеру и её цель в плоскости экрана, прокрутка приближает/отдаляет. Перемещение сохраняет дистанцию и направление взгляда; последующее вращение идёт вокруг перемещённой цели. «Сброс камеры» восстанавливает и позицию, и цель.

Реализованы этапы 1–10: основание WebGPU, пересечения, RGB path tracer, сплошное стекло, спектральный PT, RGB и спектральный SPPM, конечная сцена Suzanne и интерактивный интерфейс. Рендерер накапливает непрямой свет, перенос цвета и мягкие тени; path tracer использует NEE, power-heuristic MIS и Russian roulette после пятого взаимодействия. Глубина пресетов: Preview — 8, Reference — 64, Quality — 32; вручную доступна 1–64. Конечная глубина ограничивает оценку переноса; абсолютная несмещённость не заявляется. Физическое ядро сверяется с [PBRT: A Better Path Tracer](https://pbr-book.org/4ed/Light_Transport_I_Surface_Reflection/A_Better_Path_Tracer).

Каноническая численная сцена содержит открытую спереди коробку Корнелла 2×2×2 м, потолочный прямоугольник и единую замкнутую Suzanne из N-BK7; интерактивная стартовая сцена использует исходную Suzanne, описанную ниже. Ширина модели — 1,2 м, центр bounding box — `(0,1,0)`, камера направлена в центр с вертикальным FOV 40°. Контрольная сфера доступна через «Сцена» или `/?scene=control`. Worker проверяет меши, запекает affine transforms в мировые координаты и строит бинарный SAH BVH с 16 корзинами. Размер узла — 32 байта, обычного листа — до 4 треугольников, глубина ограничена 48 уровнями при стеке GPU из 64 элементов. Упаковка основана на WGSL reflection из `webgpu-utils`.

GPU обходит ближайший дочерний узел первым и предоставляет `closestHit`/`anyHit`. Пересечение треугольников использует sheared ray-space edge functions по [PBRT](https://pbr-book.org/4ed/Shapes/Triangle_Meshes). Ошибки индексов, стека и нечисловых значений диагностируются явно. Проверена устойчивость на фиксированном наборе лучей и текущем масштабе сцены; произвольные экстремальные координаты не проверялись.

Перетаскивание canvas вращает камеру, колесо меняет расстояние, кнопка сбрасывает камеру. Направление вращения по Y исправлено. При движении автоматически включается RGB Preview; после 250 мс покоя возвращаются выбранные настройки. Автоматический Preview можно отключить. Доступны диагностические виды normal, depth, material, wavelength, PT path length, BVH visits и photon density. Light-only и BSDF-only предназначены для сравнения с MIS. Экспозиция, tone mapping и denoiser сохраняют накопление; камера, сцена, разрешение и настройки интегратора сбрасывают его. При паузе изменение камеры выполняет полный новый проход, затем накопление останавливается.

Raw accumulation хранится в f32 отдельно от отображаемой `rgba16float` текстуры. Обычный PT запускается пакетами 48×48 пикселей; интерактивный Preview выполняет полный проход с малым пиксельным бюджетом. spp растёт после полного прохода всех tiles. Экран и фильтр используют отдельный снимок завершённого изображения: очистка накопления и незавершённые плитки не создают чёрных вспышек. Точное число samples каждого пикселя доступно в линейном `capture()`. PT использует 7 storage-buffer bindings, каждый SPPM pass — не более 8; optional features для переноса света не требуются.

Внутреннее разрешение сохраняет соотношение сторон. Preview использует бюджет 160×120; Reference и Quality — 640×480. Доступны 320×240, 960×720 и 1920×1080; фактическая площадь ограничивается бюджетом управляемой памяти и device limits. Профили памяти — Integrated 192 MiB и Desktop 384 MiB, вручную 64–384 MiB. Показанная память учитывает постоянные управляемые ресурсы, но не временный export readback, память драйвера и canvas swapchain. Время завершения включает CPU и ожидание очереди. При доступном `timestamp-query` дополнительно показывается GPU-время порции интегратора, исключая отдельный проход фильтра/отображения; без поддержки остаётся грубое completion time. Одновременно выполняется не более одной render-порции; следующая отправляется после завершения текущей.

Sampler использует 512 Sobol dimensions и nested binary Owen scrambling на всех 24 битах f32-сэмпла. Размеры камеры и каждого взаимодействия закреплены. Готовый ресурс входит в проект; повторная подготовка: `npm run assets:sobol` (нужен интернет). Источник закреплён commit SHA, метаданные и лицензии хранятся рядом с ресурсом.

Контрольный кадр воспроизводится командой `npm run capture:control`: скрипт сам запускает и завершает Vite на порту 5175 и Chrome. Этот кадр предназначен для регрессии GPU-движка. Независимая проверка прямого света использует детерминированную численную квадратуру и сравнивает MIS/light/BSDF на 65 536 путях.

По умолчанию открывается **Suzanne high poly** из `assets/Suzanne.obj` с включённой галочкой «Замкнуть модель»: быстрый первый Preview, затем Quality со спектральным SPPM и пространственным denoiser. Контрольная сфера по `/?scene=control` изначально диффузная, RGB PT. Материал доступен через «Материал», RGB/спектральный режим — через «Перенос», PT/SPPM — через «Интегратор». Панель справа содержит сгруппированные настройки; страница занимает окно без прокрутки, длинные группы прокручиваются внутри панели. PNG отображения и raw RGB PFM с JSON-метаданными скачиваются из интерфейса. CPU-сцена сохраняется для восстановления ресурсов после потери device.

Проверены восстановление после уничтожения device, стандартные device limits, отсутствие optional features, высокий DPR и production-сборка через локальный статический HTTPS-сервер. Результаты качества и браузерной матрицы: [приёмка этапа 10](docs/acceptance.md). Фактические результаты локального запуска записаны в [статусе реализации](docs/implementation-status.md).
## Стекло: этап 4

Пресет «Стекло RGB» задаёт сплошной объём с IOR 1.5 и RGB-поглощением `[0.15, 0.03, 0.01]` в обратных метрах. При смене материала накопление сбрасывается; глубина в новом интерфейсе остаётся выбранной пользователем. Quality задаёт глубину 32. «Диффузный» сохраняет контрольный материал предыдущего этапа.

Диэлектрик использует точный Fresnel, Snell, TIR, Beer–Lambert и delta-события без неприменимого continuous MIS. Radiance transmission учитывает η²; отдельный importance-режим BSDF проверен для будущего photon tracer. Вложенные и пересекающиеся стеклянные объёмы не поддерживаются. Открытые или неверно ориентированные сетки отклоняются; обнаруженная несогласованная граница или выход из незавершённого объёма диагностируется ошибкой 4.

Стеклянный BSDF использует сглаженные shading-нормали, границы среды — геометрические. События с неверной геометрической стороной получают нулевой вес. Adjoint-поправка для importance-переноса проверена отдельно; diffuse BSDF пока сохраняет геометрическую нормаль.

`npm run capture:control -- --glass` сохраняет отдельные [PNG](docs/validation/stage4-cornell.png), PFM и JSON для этапа 4, не перезаписывая этап 3. Это GPU regression capture, а не независимый эталон.

## Спектральный PT: этап 5

Выберите «Перенос → Спектральный» и «Материал → N-BK7». Пресет «N-BK7 без дисперсии» сохраняет то же спектральное поглощение и фиксирует IOR на d-линии 587.6 нм. В RGB-режиме оба N-BK7 пресета используют этот фиксированный IOR.

Одна длина волны равномерно выбирается на путь в диапазоне 360–830 нм: `p(λ)=1/470 nm⁻¹`, Sobol dimension 2. Свет, BSDF, IOR и поглощение оцениваются на этой же λ. Накопление — CIE XYZ с весом `L(λ)·CIE(λ)/(p(λ)·106.856895)`. Перевод в линейный sRGB выполняется после усреднения; gamut clipping, экспозиция и tone mapping относятся только к отображению. `capture()` возвращает `linearXyz`, `linearRgb` и `accumulationSpace`; отрицательные компоненты raw RGB сохраняются.

CIE 1931 2° и D65 взяты из закреплённой версии PBRT, источник нормирован на Y=1. Стены используют явно заданные табличные демонстрационные спектры, а не измеренные спектры Cornell. Нейтральным RGB-материалам соответствует плоский спектр; для остальных спектральный режим требует явных таблиц. Автоматического RGB-to-spectrum восстановления нет.

Sellmeier N-BK7 и внутреннее пропускание взяты из [SCHOTT, страница 13](https://www.schott.com/en-gb/products/optical-glass/-/media/Project/OnEx/Products/O/optical-glass/Downloads/schott-optical-glass-collection-datasheets-english-may2019.pdf?rev=5358bb64e13a44f2b37f5065490509af). Для IOR nm переводятся в µm; `σa=-ln(τi)/0.01 m`, затем коэффициент поглощения линейно интерполируется. Коэффициенты и источники включены в `public/assets/spectra.json`; лицензия и copyright notices находятся рядом. Повторная подготовка: `npm run assets:spectra`.

`npm run capture:control -- --spectral` сохраняет [контрольный PNG](docs/validation/stage5-cornell.png), RGB PFM, отдельный XYZ PFM, настройки и [численную приёмку](docs/validation/stage5-spectral-checks.json). Закрытая 60° призма в GPU-тесте разделяет 400–800 нм на 2.25°; при постоянном IOR разделение исчезает. На 128 spp обычный спектральный PT ещё заметно шумит, особенно в каустике. Спектральный photon gather и denoiser относятся к следующим этапам.

## RGB SPPM: этап 6

Выберите «Материал → Диэлектрик», «Перенос → RGB» и «Интегратор → SPPM». Установите глубину 32 для обычного сравнения. По умолчанию испускается 16 384 фотонных пути на итерацию пакетами по 1 024; начальный радиус — 0.03 м. Параметры доступны в панели и через `setSettings()`.

Camera pass проходит delta-события до первой диффузной поверхности и отдельно оценивает прямой свет через NEE. Photon pass пропускает первое прямое диффузное попадание, сохраняет последующие, в том числе после стекла, и продолжает путь после diffuse scattering. Каждый путь резервирует `maxDepth+1` слотов: заполнение пакета не отбрасывает энергию. Пространственный hash использует только целочисленные atomic heads; один поток на visible point суммирует поток в f32, проверяя координаты ячейки, расстояние, поверхность и нормаль.

Progressive update с α=2/3 выполняется один раз после всех пакетов, по [PBRT SPPM](https://pbr-book.org/3ed-2018/Light_Transport_III_Bidirectional_Methods/Stochastic_Progressive_Photon_Mapping). Нормировка учитывает все испущенные пути, включая промахи. При нуле попаданий радиус, N и τ сохраняются. Camera/gather portions ограничены 64×64 пикселями после калибровки на Intel UHD. Отображение и `capture()` используют последнюю завершённую итерацию; частичная итерация её не меняет. Счётчик `samples` означает итерации SPPM, `emittedPhotons` — испущенные пути. Смена камеры или настроек сбрасывает всю историю; экспозиция её сохраняет.

Visible point и история занимают 160 байт на пиксель, photon — 80 байт; размеры бюджета берутся из WGSL. Буферы проверяются по реальным device limits и освобождаются при возврате в PT. GPU-тесты проверяют hash-коллизии против brute force, progressive update, нулевые попадания, ошибочные ссылки, прямой свет против квадратуры, неизменность результата при разбиении пакетов и отмену итерации.

`npm run capture:control -- --sppm` сохраняет [PNG](docs/validation/stage6-cornell.png), линейный PFM, настройки, [сходимость 8/16/32/64 итераций](docs/validation/stage6-convergence.json) и [проверку hash](docs/validation/stage6-hash-checks.json). Кадр 128×96 на 64 итерациях использует 1 048 576 путей; под сферой видна каустика. Конечный радиус создаёт kernel bias; полная энергетическая приёмка и оценка влияния радиуса относятся к этапу 10.

## Спектральный SPPM: этап 7

Выберите «Перенос → Спектральный», «Интегратор → SPPM» и «Материал → Диэлектрик» с включённой дисперсией. IOR задаётся при 587,6 нм, число Аббе управляет моделью Cauchy.

Одна λ используется всеми camera/photon subpaths итерации. Owen–Sobol dimension 2 с общим stream ID стратифицирует длины волн между итерациями; выровненные блоки из 2ⁿ итераций покрывают 2ⁿ strata. Emission, reflectance, IOR и Beer–Lambert используют ту же λ. Камерный throughput и photon flux не делятся на PDF независимо: `CIE(λ)/(p(λ)·106.856895)` применяется ровно один раз к direct и весу visible point. Photon flux остаётся спектральным скаляром в существующем vec3 layout; gather и progressive statistics накапливают XYZ. Размер буферов и предел 8 storage bindings не изменились.

`capture()` сохраняет raw XYZ и отрицательные компоненты линейного RGB. Экспозиция не меняет их; RGB/spectral, PT/SPPM и смена камеры очищают историю, включая частичную итерацию. Общая λ даёт заметный цветовой шум на первых итерациях; на 128 итерациях контрольный кадр ещё не считается финальным изображением.

`npm run capture:control -- --sppm --spectral` сохраняет [PNG](docs/validation/stage7-cornell.png), RGB/XYZ PFM и [сходимость](docs/validation/stage7-convergence.json). Контроль: 128×96, 128 итераций, 2 097 152 пути, N-BK7, radius0.03, depth32. Это GPU regression capture.

Независимые численные проверки используют интеграл D65, квадратуру двух Lambertian propagation kernels и угловую квадратуру стеклянной пластины с внутренними отражениями. Реальный photon pass призмы проверяется против независимых CPU Snell/Fresnel, пересечений и Beer–Lambert; при постоянном IOR разделение попаданий исчезает. Для внешней приёмки есть `npm run validate:spectral-sppm -- --pbrt <путь к pbrt.exe>`; отдельный случай: `--case prism`, `--case slab`, `--case cornell` или `--case constant`. Нужен PBRT v4 commit `b4ce9687e6c695f5582997c61b0c66cf064bdb4a`, CPU build. Исходники: [mmp/pbrt-v4](https://github.com/mmp/pbrt-v4); сборка через CMake/MSVC, targets `pbrt_exe` и `imgtool`.

Экспорт использует одинаковые world triangles, shading normals, табличные спектры и medium absorption. PBRT автоматически нормирует площадной свет: `scale` восстанавливает исходную спектральную radiance, а ISO `100/106.856895` согласует выход CIE1931 с нормированным XYZ движка. White balance выключен, box filter соответствует pixel jitter. Два независимых PBRT seed проверяют устойчивость средней энергии; результаты и `.pbrt` сцены сохраняются в `docs/validation/stage7-*-comparison.json` и соответствующих PFM. Критерии: разброс reference ROI ≤2%, ошибка SPPM ROI ≤5%. Эти контрольные случаи не заменяют полную приёмку конечной сцены, радиусов, глубин и браузерной матрицы.

## Интерактивное управление: этап 9

Viewport и боковая панель занимают окно без прокрутки страницы. Настройки сгруппированы по рендеру, камере, сцене и свету, материалу, фотонам, отображению и памяти. Все элементы управления работают; декоративных инструментов и статичных осей нет. Разметку можно расширять по мере появления функций редактора.

Preview использует RGB PT depth8, Reference — спектральный PT depth64, Quality — спектральный SPPM depth32. Во время вращения включается Preview, через 250 мс покоя возвращается выбранный режим. Вертикальное управление исправлено. Последний полный кадр остаётся на экране до завершения нового прохода, поэтому очищение накопления и частичные тайлы не создают чёрных вспышек.

Пространственный à-trous использует нормали, глубину и локальную оценку дисперсии яркости; это не оценка ошибки сходимости. Стеклянные первые поверхности по умолчанию не фильтруются. Фильтр, экспозиция и tone mapping не изменяют raw-накопление. Подход основан на [работе Dammertz et al.](https://jo.dreggn.org/home/2010_atrous.pdf).

PNG экспортирует отображаемый результат, PFM — линейный RGB с отрицательными компонентами, JSON — настройки и диапазон накопленных samples. `npm run capture:editor` воспроизводит экспорт через настоящие кнопки и сохраняет [интерфейс](docs/validation/stage9-editor.png), raw/filtered PNG, PFM и результаты проверок. Это проверка интерактивного режима; результаты приёмки изображения и сравнения Suzanne с PBRT приведены в [этапе 10](docs/acceptance.md).

## Suzanne: этап 8

Готовый меш содержит 49 370 вершин и 98 736 треугольников, включая сглаженные нормали. Бинарный ресурс 2,37 MB входит в сборку; загрузчик проверяет SHA-256 и layout. Blender и интернет для запуска приложения не нужны. Смена сцены сохраняет положение камеры и освобождает предыдущие GPU-ресурсы.

В списке объектов доступны **Suzanne high poly** (стартовый вариант из `assets/Suzanne.obj`, 251 904 треугольника до ремонта) и прежняя **Suzanne**. Прямые ссылки: `/?scene=suzanne-high-poly` и `/?scene=suzanne`. High poly OBJ включается Vite в production-сборку без изменения исходного файла; обе модели загружаются и ремонтируются в Worker с независимыми кешами.

В варианте **Suzanne** используется [исходная Suzanne из Blender](assets/suzanne-original.obj): 507 вершин, 500 исходных полигонов и 968 треугольников штатной render-триангуляции Blender. Экспорт не применяет subdivision, remesh, сглаживание или склейку и сохраняет исходные координаты с точностью f32; выполняется только перевод осей в Y-up. Приложение вписывает модель до 1,2 м. Галочка «Замкнуть модель» включена по умолчанию для всех четырёх моделей и новых OBJ: в Worker закрываются четыре отверстия Suzanne, получается 1002 треугольника. Все четыре встроенные модели хранятся в `assets` как OBJ и используют единый Worker-импортёр с отдельными кешами исходной и замкнутой версии. Бинарные меши, их формат и генераторы запекания удалены. Диагностические сцены тоже используют исходные OBJ. `sobol.bin` остаётся таблицей семплирования, а не геометрией.

Сведения об исходной Suzanne — в [SUZANNE-NOTICES.txt](public/assets/SUZANNE-NOTICES.txt). Сохранённые старые изображения и измерения относятся к прежней обработанной сетке и не описывают текущие OBJ-сцены.

Параметры: 256×192, 256 спектральных SPPM-итераций, seed17, depth32, radius0.03. Сцена соответствует размерам и размещению из плана; проверка всей Suzanne против PBRT и итоговые кадры приведены в [приёмке этапа 10](docs/acceptance.md).

## Редактор материалов

В списке три типа: диффузный, диэлектрик и текстурный. Текстуры выбираются ниже (мрамор / лава); каждый вариант сохраняет свои параметры при переключении. Диэлектрик имеет режим Авто / Объёмный / Тонкий, IOR, дисперсию Cauchy с числом Аббе, цвет пропускания, эталонную глубину и шероховатость. Авто использует объёмный перенос для замкнутой геометрии; принудительный объёмный режим проверяется и в движке.

Цвет sRGB переводится в линейное пропускание. В объёме коэффициент поглощения равен −ln(T)/глубина (метры), нулевое T ограничивается 0,0001. В тонком стекле цвет применяется на поверхности; глубина не используется. Спектральное восстановление цвета из RGB — художественное приближение. Начальное синее стекло сохраняет RGB-коэффициенты [7, 4, 0.08] при глубине 0,1 м.

Шероховатость 0 сохраняет гладкий перенос. Для положительных значений используется изотропный GGX с выборкой видимых микронормалей и согласованными BSDF/PDF по [PBRT rough dielectric](https://www.pbr-book.org/4ed/Reflection_Models/Rough_Dielectric_BSDF). Тонкий вариант использует взаимное приближение рассеивания вокруг прямого прохождения, без объёмной толщины. PT оценивает прямой свет с MIS; SPPM хранит направление камеры и фотонов, вычисляет BSDF при сборе и разделяет оболочки. Первое прямое попадание фотона исключено, поскольку его оценивает NEE.

Подсказки доступны через i, числовые параметры сбрасываются нажатием колёсика. JSON при Raw PFM сохраняет параметры материала и фактический режим диэлектрика. Старые функции сцен и названия материалов для численных проверок остаются доступными.
