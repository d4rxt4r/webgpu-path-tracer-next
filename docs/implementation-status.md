# Статус реализации

## 2026-10-03 — основание (этап 1)

Создан Git-репозиторий и приложение TypeScript/Vite с compute-to-canvas. Диагностическое изображение не является результатом PT или SPPM.

Проверено локально:

- Windows, Node.js 24.11.1, установленный Chrome, headless, без специальных WebGPU-флагов.
- Системный GPU: Intel UHD Graphics; WebGPU-адаптер сообщает `intel gen-12lp`.
- Compute + display pipelines компилируются и рисуют кадр. Снимок `test-results/foundation.png` визуально проверен.
- В тестовом окне внутреннее изображение 869×353, управляемые ресурсы 2.34 MiB. Это один диагностический запуск, не benchmark будущего path tracer.
- Pause/resume, resize и понятная ошибка при отсутствии `navigator.gpu`: 2 браузерных теста прошли.
- Ограничение разрешения, DPR, device dimension limit и некорректные входы: 3 CPU-теста прошли.
- `npm run build`, `npm test`, `npm run test:browser`, `npm audit` завершились успешно; audit сообщает 0 уязвимостей.

Не проверены: принудительная потеря устройства, HTTPS-развёртывание, Edge/Firefox/Safari и искусственно ограниченные device limits. Восстановление устройства реализовано, но не считается принятым только на основании статического анализа.

На момент окончания этапа 1 следующий шаг: камера, геометрия, Worker, SAH BVH и сверка GPU-пересечений с CPU brute force.

## 2026-10-03 — пересечения (этап 2)

Реализованы описание CPU-сцены, pinhole camera, orbit/zoom/reset, проверка геометрии, запекание affine transforms и нормалей, Worker с revision и отменой устаревших задач, world-space binned SAH BVH. Обычный лист содержит до 4 треугольников; при достижении предела глубины builder создаёт лист без потери примитивов. Стек GPU ограничен 64 элементами, builder — 48 уровнями.

WGSL и CPU используют sheared ray-space edge functions по [PBRT: Triangle Meshes](https://pbr-book.org/4ed/Shapes/Triangle_Meshes). BVH обходит ближний узел первым и имеет `closestHit`/`anyHit`. Нулевые компоненты направления обработаны отдельно в AABB slabs. WGSL-layout пакуется reflection из `webgpu-utils`; размеры и смещения проверены тестами.

Сцена сейчас — коробка 2×2×2 м, потолочный прямоугольник и замкнутая контрольная сфера (972 треугольника, 571 BVH узел). Реализованы debug views normal/depth/BVH visits. Это диагностическое изображение без переноса света, не готовая стеклянная сцена.

Проверено:

- Chrome headless без специальных WebGPU-флагов на `intel gen-12lp`.
- 2 088 фиксированных лучей: GPU closest-hit и any-hit совпадают с CPU brute force по попаданию; максимальная ошибка расстояния 5.162031935235234e-7 м. На shared-edge лучах допускается другой примитив при том же расстоянии из-за f32 roundoff.
- CPU дополнительно сверяется с независимой реализацией Möller–Trumbore на случайных лучах вне рёбер.
- Лучи по граням AABB и общим рёбрам, внутри сцены, misses и ограниченный tMax.
- Повреждённый индекс BVH → ошибка 1; искусственная глубина с переполнением стека → ошибка 2; нулевое направление луча → ошибка 3. Ошибки не маскируются как misses.
- Worker cancellation; изменение камеры во время подготовки; многократная замена сцены с неизменным учётом управляемой памяти. Это проверка учёта ресурсов, не измерение памяти драйвера.
- Orbit/reset и смена debug view перерисовывают кадр при паузе.
- Снимки normal/depth визуально проверены; 10 CPU-тестов и 5 браузерных тестов прошли, production build успешен.

В тестовом окне 869×353 управляемые ресурсы занимают около 2.45 MiB. Разовое время завершения диагностического кадра около 5 мс не является benchmark будущего интегратора.

Не проверены принудительная потеря устройства, Edge/Firefox/Safari, экстремальный масштаб координат и статическое HTTPS-развёртывание. История PT/SPPM ещё не существует; кадры пересечений сбрасываются при изменении камеры/геометрии/разрешения.

На момент окончания этапа 2 следующий шаг: RGB path tracer, NEE/MIS/Russian roulette и линейное накопление.

## 2026-10-03 — RGB path tracer (этап 3)

Реализовано общее RGB-ядро: diffuse BSDF с cosine-weighted sampling, выбор треугольников площадных источников по площади, NEE с проверкой видимости, power heuristic MIS для NEE и продолженного попадания в источник, Russian roulette после пятого scattering с компенсацией. Подход соответствует [PBRT: A Better Path Tracer](https://pbr-book.org/4ed/Light_Transport_I_Surface_Reflection/A_Better_Path_Tracer).

Добавлены f32 raw accumulation, отдельное HDR-отображение, tile-dispatches 64×64 и счётчики полных spp/частичного прохода. Camera/scene/resolution/integrator changes сбрасывают историю; экспозиция её сохраняет. При изменении камеры на паузе рисуется один новый проход, затем остановка. UI показывает RGB PT, normal/depth/BVH, MIS/light/BSDF, разрешение и экспозицию. Базовая глубина 8, допустимый программный предел 64.

Sampler: Sobol directions из PBRT на закреплённом commit `b4ce9687e6c695f5582997c61b0c66cf064bdb4a`, 512 dimensions × 32 index bits, nested Owen scrambling на 24 битах используемой f32-точности. Камера использует dimensions 0–1, dimension 2 зарезервирована для wavelength; каждому bounce выделены 7 фиксированных dimensions. Данные, SHA-256, лицензии и скрипт повторной подготовки сохранены в проекте.

Проверено на Chrome headless / Intel `gen-12lp` без специальных WebGPU-флагов:

- GPU MIS/light-only/BSDF-only на 65 536 путях сравниваются с независимой квадратурой площадного света (512×512). Для красного канала reference = 0.27706349026410465; MIS = 0.277059303924716, light = 0.27706336730170733, BSDF = 0.27700042724609375. Все каналы имеют относительную ошибку менее 0.03%, предел приёмки 2%.
- PDF источника проверен на расходящихся лучах и разных emitter IDs: максимальная относительная ошибка 7.68e-7. На этой GPU ранние выходы из цикла поиска источника давали неверные PDF; вариант с одним выходом из функции прошёл численную проверку. Причина на уровне compiler/driver независимо не установлена.
- CPU/GPU Sobol samples совпали точно на контрольных значениях. CPU-тест проверяет stratification на 1 024 samples в нескольких dimensions, включая dimension 511.
- Проверка компенсации Russian roulette на 12 взаимодействиях с attenuation 0.8: среднее 0.06915283203125 против аналитического 0.06871947673600004 (около 0.63% расхождения).
- Raw capture воспроизводится побитно при фиксированных камере/seed/настройках; экспозиция сохраняет raw и samples; камера и стратегия сбрасывают их. Завершённый проход имеет одинаковый count у всех пикселей.
- Сохранились предыдущие проверки BVH, Worker cancellation, повторной смены сцены, resize и ошибок при отсутствии WebGPU.
- 15 CPU-тестов и 8 браузерных тестов прошли; production build и audit успешны.

Сохранён [контрольный PNG](validation/stage3-cornell.png), [линейный PFM](validation/stage3-cornell.pfm) и [метаданные](validation/stage3-cornell.json): 128×96, 128 spp, seed 17, depth 8, MIS, diffuse sphere. Raw-кадр и мягкая тень/перенос цвета визуально проверены. Один запуск занял около 8.57 с, постоянные управляемые ресурсы — 472 376 байт. Это локальный regression capture, не независимый эталон и не обещание производительности на других настройках.

Демонстрация пока не использует shading-normal corrections для переноса: diffuse BSDF опирается на геометрическую нормаль. Стекло ещё отвергается transport preparation с понятным сообщением. Дисперсии, каустического интегратора, denoiser и авто-перехода Preview/Quality нет. Принудительная потеря device и внешнее HTTPS-развёртывание ещё не проверены. Полная image-level энергетическая приёмка и глубины 32/64 остаются последующим этапам.

Следующий этап: Fresnel, reflection/refraction/TIR и Beer–Lambert для сплошного диэлектрика. Этапы 4–10 пока не реализованы.
