# Проверка денойза, 2026-10-08

Реализованы à-trous, bilateral и spatial NLM с участками 3×3, отдельной силой/режимом стекла, смешиванием и разделителем. По умолчанию остаются à-trous и стекло без фильтра. NLM работает на паузе; возобновление накопления возвращает оригинал.

## Условия и доказательства

- Подключённый Chrome, адаптер Intel gen-12lp, 160×120, seed 17, глубина 12.
- Один исходный кадр с 4 samples/iterations для всех девяти комбинаций фильтра и режима стекла. Ориентир — продолжение того же накопления до 32 samples/iterations, отдельно для каждого интегратора.
- SPPM: 4096 фотонов на итерацию, пакет 1024. Настройки фильтра, commit и SHA-256 исходников — в [provenance.json](provenance.json). SHA-256 JSON сцены и материал — в metrics.json каждого случая.
- Все 10 случаев сохранили raw-накопление побитово; все результаты фильтров конечны, ошибок GPU validation не получено.
- Отдельная детерминированная GPU-фикстура проверяет 18 комбинаций RGB/XYZ, алгоритмов и режимов стекла: постоянный цвет, силуэт стекло/непрозрачная поверхность, bypass, нулевое смешивание и исходную половину разделителя. Допуск постоянного цвета — один шаг FP16.
- 32 samples — шумный локальный ориентир, общий с исходником по первым четырём samples. Это не независимый физический эталон и не проверка сходимости. Центральный прямоугольник стекла — ограниченная область, а не полная маска объекта.

## Ошибка в центральной области стекла

MSE в линейном RGB. Область: x 42–58%, y 52–78% кадра. Во всех фильтруемых столбцах выбран режим стекла «по изображению». Полная MSE и режимы «без фильтра»/«по поверхности» сохранены в metrics.json.

На этой области все три фильтра снизили ошибку. Это не означает улучшение каждого участка: на RGB SPPM все фильтры увеличили полную MSE кадра; на RGB PT à-trous и NLM тоже увеличили полную MSE. Визуально à-trous сильнее сглаживает мелкие детали и каустику; bilateral оставляет больше шума; NLM даёт ещё один компромисс, но не гарантированное превосходство.

## Время и память

Один прогрев каждой настройки, затем один измеренный запуск. Значения ниже — диапазон по десяти случаям с режимом стекла «по изображению», не статистический benchmark. Генерация guide исключена из измеренного GPU-времени. Время завершения включает submit и ожидание readback изображения/таймстампов; это не GPU timestamp и не стоимость только фильтра.

| Алгоритм | GPU timestamp, мс | Завершение с readback, мс |
| --- | ---: | ---: |
| atrous-image | 0.262–0.328 | 6.8–10.1 |
| bilateral-image | 0.066–0.197 | 4.6–9.5 |
| nlm-image | 1.049–1.507 | 5.4–11.7 |

Ресурсы денойзера при 160×120: 614720 байт (guide, две текстуры результата и пять uniform buffers). NLM использует те же текстуры. Эти цифры не характеризуют 4K, high-poly Suzanne или другие адаптеры.

## Повторение проверки

Итоговые проверки: сборка прошла, 127 unit-тестов прошли, пять выбранных браузерных проверок прошли. Регрессия PNG выявила гонку компиляции фильтра; экспорт теперь дожидается подготовки денойзера, и тест снова подтвердил сглаживание, неизменность raw и стекла, сохранение полного кадра при tiled reset.

Дополнительно в подключённом Chrome проверена Suzanne при spectral SPPM: 408×187, 64 итерации, NLM, стекло «по изображению», смешивание 70%, разделитель 50%. [Снимок интерфейса](editor-nlm-comparison.png) показывает исходник слева и результат справа. Это функциональный просмотр; качество high-poly Suzanne и 4K этим не подтверждается.

`npm test` и `npm run build` проверяют CPU/TypeScript и сборку. `npm run test:browser -- tests/browser/denoise.spec.ts tests/browser/settings-link.spec.ts` запускает GPU-фикстуру, сохранность накопления PT/spectral SPPM, управление NLM и восстановление настроек.

Для повторения полной матрицы открыть `/tests/fixtures/denoise.html` на Vite и импортировать `/src/debug/compare-denoise.ts`. Вызвать `compareDenoise({integrator, mode, roughness, low:4, reference:32})` для PT/SPPM, RGB/spectral, roughness 0/0.12; дополнительно spectral PT/SPPM с `dispersion:true`. Запускать последовательно; результаты новых запусков сохранять в отдельный каталог.
